静的な HTML/JavaScript のじゃんけん RPG です。GitHub Pages で公開し、認証とアカウントごとの保存に Firebase を使います。

## アカウント機能

- メールアドレスとパスワードでのログイン・新規登録。
- ログイン、新規登録、再設定、ログアウトはスタート画面とゲーム中のアカウント窓から操作できます。歯車の「アカウント」はその場で窓を開き、「ログイン」はスタート画面へ戻ります。
- ログアウト時は Firebase のセッションを終了し、ゲーム画面を再読み込みします。
- キャラ、クリア状況、カード、コイン、途中の戦闘、並べ替え、ニックネーム、カエデの姿を UID ごとに分離します。
- パスワード再設定は Firebase が送るメール内のリンクで行います。
- ゲストの既存データは元の保存先に残し、ログイン後のデータには自動で混ぜません。
- 音量・演出速度と表示幅は端末の設定として共通です。

## パスワードと保存の扱い

パスワードは Firebase Authentication SDK に直接渡します。アプリは平文パスワードも独自のパスワードハッシュも保存しません。ゲーム用 localStorage、Realtime Database、URL、ログには送信・記録しません。入力欄は送信・ゲーム開始・操作切り替え時に空にします。

認証トークンの管理は Firebase SDK に任せ、認証セッションの永続化は LOCAL を使い、ログアウトまたは90日間の利用なしで終了します。最終利用時刻だけを端末に保存します。Firebase の SDK 設定にある公開 API キーは管理者用の秘密鍵ではありません。管理者資格情報はこのリポジトリに置きません。

ゲームデータのクラウド保存先は `/jq/users/<uid>/data` です。`database.rules.json` の所有者チェックにより、本人のみ読み書きできます。保存可能な項目はゲームデータの8項目（プロフィール・塔の進行を含む）に限定し、`password` などの未定義の項目は拒否します。オンライン対戦の既存ルールは維持しています。

ページが動作している間は保存先の UID を固定します。アカウントが変わったら画面を覆って再読み込みするため、前ユーザーの遅延処理が次ユーザーの保存先に書き込むことを防ぎます。

## Firebase の設定

1. `index.html` の `FIREBASE_CONFIG` を対象プロジェクトの Web アプリ設定と合わせます。
2. Authentication のログイン方法で「メール / パスワード」と、オンライン対戦用の「匿名」を有効にします。
3. Realtime Database に `database.rules.json` を公開します。JSON ファイルを GitHub に置くだけでは、実際のアクセス制限は変更されません。
4. Authentication のメールテンプレートと承認済みドメインを確認します。
5. パスワード再設定メールの到着確認は、利用者自身のメールアドレスで行ってください。

Firebase 公式資料: [メールとパスワードによる認証](https://firebase.google.com/docs/auth/web/password-auth)、[パスワード再設定](https://firebase.google.com/docs/auth/web/manage-users)、[所有者によるアクセス制限](https://firebase.google.com/docs/database/security/rules-conditions)。
